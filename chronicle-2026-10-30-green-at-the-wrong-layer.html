Green at the Wrong Layer

October 30, 2026 Observability • Security • Feeds • Networking • Changing of the Guard

The last entry was about moving the analyzer onto better hardware. What came after was a month of two very different kinds of work stacked on top of each other. The visible half went roughly to plan — features shipped, the site got more useful, traffic roughly doubled. The other half was a run of things that all failed the same way: they reported perfectly healthy at the layer I happened to be looking at, and were broken one layer down. Every fix turned out to be the same move — stop checking where it's convenient, check where the thing actually runs.

The Visible Half

First the part worth celebrating, briefly, because it's the reason any of the rest matters. The Song Analyzer learned to hand you its results instead of just displaying them: the chords it finds now export as a MIDI file — a single track you can drag into Logic or Ableton to drive one instrument, or split across parts. It transcribes lyrics on the GPU and streams them in as it goes, in whichever language you pick. It gained practice controls — transpose, capo, playback speed, an A/B loop — and chord diagrams encoded shape-first so they still read if you're colour-blind. I added a prosody guide with a scansion tool, because nobody teaches songwriters to count stresses. And the analyzer itself finished splitting across two machines, chords and tempo on the CPU box, lyrics on the GPU box.

The quietest of these is the one I'm most pleased with. The analyzer page used to be a dead end — someone arrived from a search, got their chords, and left past sixty pages about exactly what to do next. It now reads its own results and offers the right page for this song: when it finds a chord that doesn't belong to the key, it offers to explain why that chord works anyway. That isn't a related-links box. The page knows the key and the chords, so it can point at the one thing you'd actually be curious about.

Feeds Unavailable

The site has two "dispatch" pages — live feeds of AI and music-tech news. One day they went blank and said feed unavailable. My first fix made the failure visible instead of a silent hang, which felt like progress and solved nothing: the feeds were still dead. They'd been fetched through two free public proxies, and both had died in the same window for unrelated reasons — one had put a bot challenge in front of its API, the other's server had simply stopped answering.

So I went looking for a replacement proxy and found a working one. It returned the feeds and, when I checked, sent the right cross-origin header. I wired it in, declared victory, and it didn't work at all. The browser check I'd built to be honest with myself caught why: the proxy sent that permissive header to a server, and nothing — no header at all — to a real browser. I'd tested a CORS proxy with a tool that isn't a browser, which is the one thing that can't tell you whether a CORS proxy works. Testing it with anything but a browser doesn't test it.

One of the seven public proxies I tried literally answered: "banned for abuse. Do not use this proxy. Create your own cors proxy." That is the whole state of that ecosystem in one error message.

So I stopped needing one. The reason a browser can't fetch a feed is a rule that applies to browsers and nothing else — a script on a build server has no such limit. So the fetching moved there: a workflow pulls every feed on a schedule and commits the result as a plain file the site serves from its own origin. No proxy, no third party, nothing to log into, and it fixed all four pages that read feeds — including the one on the homepage I'd overlooked entirely until a screenshot showed me a layout I didn't recognise.

Who's Actually Answering

While chasing all that, I kept checking whether the analyzer was up by asking its public health endpoint, which kept answering yes. It was telling the truth and I was asking the wrong question. "Is the hostname answering" is not "is the machine I think is behind it answering." The endpoint said healthy while a different box than I believed — a warm spare — was quietly serving everything in a degraded single-slot mode. Its own report gave it away once I read past the first word: three analysis slots on the real box, one on the spare.

This is the second time the estate has fooled me the same way. Back in the summer a machine at my workplace served the public site for weeks while everyone read a different box's status, because up-or-down was the only thing the check reported and both answers look identical from outside. So the monitor now prints which machine answered on every run — the fingerprint fields that differ between boxes — and the blind spot that hid a production server twice is closed.

The Hole the Advisory Didn't Mention

Late in the month a security advisory went around about a pair of critical flaws in PHP. It doesn't touch this site — there's no PHP anywhere in it, and the host can't execute any. Easy to file under "not my problem." But it was a good prompt to actually look, and looking found a real one that no advisory would ever have named.

Every page that renders those news feeds built each headline's link the same way, and the helper that was supposed to make third-party text safe escaped the wrong characters — everything except quotes. A feed item whose link contained a quote could close the attribute and write its own, an event handler included. I wrote a proof of concept, and it ran: a crafted feed fired script on all four pages. A second path needed no quotes at all. It was reachable precisely because the pages render other people's content, and it mattered precisely because roughly fifteen thousand people a month were loading it. The fix was two independent guards and a content-security policy. The lesson was the month's lesson again: the vulnerability lived at the layer where a browser renders the markup, which is not the layer where the code reads fine.

Two Routers I Didn't Know I Had

Then the network, which is where "check where it actually runs" stopped being a metaphor. Machines I was sure sat on one flat home network kept vanishing from the router's list. I spent a while diagnosing boxes that weren't broken before the real shape surfaced: there were two routers daisy-chained — an EdgeRouter I'd half-forgotten feeding the main one — each handing out its own addresses, so my machines were split across two networks that couldn't see each other. The diagram in my head said one subnet. The cabling said two.

I made it worse before better — I factory-reset the upstream router thinking it was a switch, which briefly took out more than it fixed — and then made the right call, which was the boring one: collapse everything onto a single segment and stop using a router to do a switch's job. What I actually wanted all along was more ports, and the tool for more ports is a dumb unmanaged switch, not a second router with opinions. A used sixteen-port switch does the whole thing with nothing to log into and no network of its own to accidentally create.

Chords Out of Tune

A smaller one, but it's the same shape so it belongs here. Playing chords on the synth, something sounded faintly wrong — fine on a single note, off across a progression. The tuning maths was correct; I'd verified it. So I stopped reading the code and measured the actual output, and the spectrum told the story at once: the default patch layered two sawtooths detuned fourteen cents apart, which is a gorgeous lead and a terrible chord. A single A didn't produce one pitch; it produced two, a few cents either side, beating against each other. A triad arrived as six tones, not three. Narrowing the detune fixed it, and I'd never have found it by staring at arithmetic that was already right. You have to look at the thing that comes out, not the thing you wrote.

Changing of the Guard

Underneath all of it, a quieter shift finished happening this month, and it's worth marking because it changes what this project even is.

The early version of this site ran on agents. There was an OpenClaw gateway, a pile of API tokens, and Telegram as the main way I talked to it — I'd message a model from my phone and it would build pages, commit code, run things. That era is documented on the architecture page, and the ideas in it still hold, but it's the past now. The work moved to Claude Code, which is a different relationship: less "wind up an autonomous agent and hope," more sitting beside a capable one and steering. The box that used to run the agent gateway is now a liability I'm decommissioning — a cheap machine at my workplace still holding a key that reaches my whole home network, which is exactly the kind of thing you clean up once you start thinking like an administrator instead of an operator.

And that's the direction from here: security. The network got torn down and rebuilt partly so it would be something I can reason about and audit, not just extend. I stood up a dedicated box for it, drew out the estate's SSH trust model so the blast-radius logic is visible instead of implied — a few admin machines reach every server, the servers reach nothing, so a compromised server is a dead end rather than a doorway. The next real work is to turn those tools on my own infrastructure: scan what's actually exposed, prove the services bind where they claim to, check the rules on the database that quietly accepts writes. I've spent this month learning, the hard way and repeatedly, that a thing can look healthy from the outside and be wrong underneath. Pointing that lesson at my own security posture, on purpose, is the obvious next move.

One note on motive, since none of this earns a cent. I've never meant to profit from it. The whole project is somewhere to chase knowledge, to explore, to build things and design them properly — and the traffic was never revenue. It's evidence. Fifteen thousand people a month using something I stood up and keep running is a record that will still be here later, the kind you can point to: I built this, and people came. That's worth more to me than whatever it could have charged — and it's exactly why getting it working, and keeping it honest underneath, is the part I care about.

What I'd Take From It

Every failure this month — the feeds, the health check, the injection, the network, even the synth — had the same signature. It passed at the layer I checked. The proxy answered a server. The endpoint answered a ping. The escaping function escaped something. The diagram showed one network. The tuning code computed the right numbers. And each was broken one layer down, where a browser renders, where a specific machine responds, where the cables actually run, where the sound actually comes out.

The fix was never clever. It was moving the check to where the thing happens and looking there. That's a dull lesson and an expensive one to keep re-learning, so I'm writing it down: a green light tells you the layer you're watching is fine. It tells you nothing about the one you're not.

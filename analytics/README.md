# Analytics

Traffic numbers, committed into the repository rather than left in a dashboard.

## Why this exists

The agent that works on this site runs in a sandbox whose network policy
reaches **GitHub and nothing else**. Not `methodictruth.com`, not
`api.methodictruth.com`, not Firebase, not Cloudflare's API — all blocked.

That is why `/health` on the analyzer, which is a good endpoint, still cannot
answer a question asked here: someone has to copy its output by hand. Anything
that needs to be *seen* has to arrive through the repository.

So a scheduled job fetches the numbers where the network is open — a GitHub
runner — and commits them here.

It also builds something no dashboard provides: an **append-only daily
history**. A dashboard shows the last 30 days and forgets. Growth is a
comparison between windows, so without history the question "is it growing?"
cannot be answered at all, only guessed at from the shape of a chart.

## Files

| File | |
| --- | --- |
| `REPORT.md` | The readable summary. Start here. |
| `history.json` | Append-only daily rows. The part that makes trends possible. |
| `latest.json` | Raw last-run output, for machine use. |

All three are regenerated by `.github/workflows/analytics.yml`, daily at
07:10 UTC and on demand via **Actions → Collect Analytics → Run workflow**.

## Setup

Repository → Settings → Secrets and variables → Actions.

**Secrets**

| Name | Where to get it |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | Cloudflare → My Profile → API Tokens → Create Token. It needs exactly one permission: **Zone → Analytics → Read**. Do not use a Global API Key. |
| `CLOUDFLARE_ZONE_ID` | Cloudflare dashboard → the domain → Overview, right-hand column. |
| `FIREBASE_AUTH` | Only if the database rules deny public read, which they should. Firebase console → Project settings → Service accounts → Database secrets. |

**Variables** (optional)

| Name | Default |
| --- | --- |
| `FIREBASE_DB_URL` | `https://methodictruth-default-rtdb.firebaseio.com` |

A missing secret does not fail the run — the report names the source that was
unavailable, so a partial collection is still useful and the gap is visible
rather than silent.

## Privacy

The on-site beacon records page, referrer, screen size, user-agent and a
per-browser id. **This repository is public, so only aggregates are written
here**: counts per page, and counts per referring *host* — never full referring
URLs, never user-agent strings, never visitor ids. Raw records stay in Firebase.

If the Firebase rules currently allow public reads, they should not. Write-only
is the correct configuration for a beacon like this — otherwise anyone who
views source can read every visitor record. Setting `FIREBASE_AUTH` is what
lets this job keep working after you lock it down.
